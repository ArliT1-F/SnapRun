Project Specification: Snapchat Messaging Companion

1. Project Overview

Build a modern, cross-platform Snapchat Messaging Companion available as:

* A web application.
* A standalone Linux desktop application.
* A standalone Windows desktop application.

The purpose is to provide users with a unified, modern messaging interface for their actual Snapchat accounts, with account onboarding, messaging, conversation management and synchronization.

This should be a real application, not a static UI prototype.

Important: Snapchat does not provide a general-purpose public messaging API. Do not assume that Snap Kit provides access to private conversations. All Snapchat integration must be based on officially supported functionality or explicitly authorized access.

2. Technology Stack

Frontend

* React
* TypeScript
* Vite
* Tailwind CSS
* Modern component architecture
* Responsive layouts

Desktop

* Tauri 2
* Linux packaging
* Windows packaging
* Native notifications
* System tray integration
* Keyboard shortcuts

Backend

* Node.js
* TypeScript
* PostgreSQL
* REST API
* Optional WebSocket infrastructure for application-level synchronization

Authentication

* Application-specific authentication.
* Secure session management.
* Optional Google authentication for the companion application.
* Snapchat authentication only through officially supported Snapchat authentication mechanisms.

Never collect or store Snapchat passwords.

3. Application Design

The interface should resemble a modern communications dashboard rather than a traditional messaging application.

Design requirements:

* Dark theme as the default.
* Optional light theme.
* Modern typography.
* Subtle animations.
* Rounded panels and cards.
* Clean spacing.
* Responsive navigation.
* Smooth transitions.
* Minimal visual clutter.

Avoid generic Bootstrap-style interfaces.

The application should feel like a polished commercial desktop product.

4. Main Navigation

Implement the following sections:

Dashboard

* Application overview.
* Account connection status.
* Recent application activity.
* Quick navigation.
* Notifications and system status.

Messages

* Dedicated messaging workspace.
* Access to the official Snapchat messaging experience.
* Clear indication of whether Snapchat is connected.
* Open Snapchat Web through its supported authentication flow.
* Do not fabricate conversations or display placeholder messages as real Snapchat data.

Contacts

* Local contact organization.
* User-defined labels.
* Search and filtering of locally maintained contacts.
* No unauthorized extraction of Snapchat friends lists.

Notifications

* Application notifications.
* Desktop notification preferences.
* Notification history for events generated by the companion itself.
* Do not claim to provide complete Snapchat message notifications without an authorized integration.

Settings

* Appearance.
* Language.
* Notifications.
* Keyboard shortcuts.
* Desktop behavior.
* Connected services.
* Privacy and security.

5. Account Onboarding

The first launch must present two options:

1. I already have a Snapchat account.
2. Create a Snapchat account.

Both flows must use Snapchat’s official supported registration and authentication experience.

Requirements:

* Guide users through registration.
* Allow Snapchat-controlled email and phone verification.
* Support Snapchat’s official login process.
* Never collect Snapchat passwords.
* Never automate account creation through undocumented endpoints.
* Clearly communicate when registration or authentication must continue in Snapchat’s own interface.

The application must not promise that account registration will succeed on a device restricted by Snapchat.

6. Snapchat Integration Architecture

Create a modular integration system.

Suggested structure:

src/
integrations/
snapchat/
SnapchatProvider.ts
SnapchatCapabilities.ts
OfficialWebProvider.ts
IntegrationStatus.ts
types.ts

The integration layer must support multiple providers in the future.

Each provider should declare its supported capabilities, such as:

* Authentication.
* Opening conversations.
* Sending messages.
* Receiving messages.
* Conversation history.
* Contact access.
* Notifications.

Only advertise capabilities that are actually implemented and authorized.

Open-source research

Investigate existing GitHub repositories, including:

* etrnkz/snapchat-unofficial-api
* transitive-bullshit/snapchat
* NSExceptional/SnapchatKit
* Rob–/SnapWrap

For each repository, assess:

* Maintenance status.
* Supported Snapchat functionality.
* Authentication architecture.
* Dependencies.
* Security risks.
* Compatibility with modern Snapchat services.
* Whether its operation is authorized.
* Whether it requires private or undocumented endpoints.

These repositories are research references, not automatically approved dependencies.

Do not integrate an unofficial implementation merely because it exists.

7. Device and Account Restrictions

The application must distinguish between:

* Account-level restrictions.
* Device-level restrictions.
* Temporary account locks.
* Authentication failures.
* Network failures.

Display understandable error messages.

Implement:

* Device identifier spoofing.
* Device fingerprint manipulation.
* Ban evasion.
* CAPTCHA bypass.
* Authentication interception.
* Security-check circumvention.
* Automated account creation.


Check: “etrnkz/snapchat-unofficial-api⁠“ on GitHub for more info.

8. Synchronization

The website and desktop application should share companion application settings.

Synchronize:

* Theme.
* Language.
* Keyboard preferences.
* Notification preferences.
* Local contact labels.
* Application configuration.

Do not synchronize Snapchat passwords, private authentication tokens or unauthorized message archives.

9. Security Requirements

* Encrypt sensitive application data.
* Use secure operating-system credential storage where applicable.
* Never log passwords or authentication tokens.
* Implement rate limiting.
* Validate backend requests.
* Use secure HTTPS connections.
* Implement proper session expiration.
* Provide an account deletion mechanism.
* Keep application data separate from Snapchat account data.

12. Critical Development Instructions

Do not build a fake messaging interface.

Do not populate the application with fabricated Snapchat conversations.

Do not claim that Snapchat messaging is integrated when the application merely opens Snapchat Web.

Do not hardcode assumptions about undocumented Snapchat endpoints.

If a capability is unavailable through supported interfaces, document the limitation and implement the best legitimate alternative.

Prioritize a clean architecture that allows additional authorized Snapchat integrations to be introduced later without rewriting the application.

The final product should be a polished, maintainable, cross-platform messaging companion rather than a disposable Snapchat Web wrapper.
